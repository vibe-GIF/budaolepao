# 步道乐跑电脑端模拟器 PoC

> **仅限授权测试**：仅用于步道乐跑团队自有沙箱/测试账号。
> 禁止外传为通用刷分工具。

## 环境

从完整源码安装 Python 3.10+ 依赖，见[根目录说明](../../README.md)。
运行部分使用 Windows 版 MuMu 的 `MuMuManager.exe` 和 `adb.exe`；没有 iOS 实现。
测试 App 需要由使用者在模拟器中完成安装、登录与必要的人工操作。

## 配置

配置位于本目录的 `config.json`，`config.example.json` 提供示例。
示例路线仅用于展示格式，不代表任意学校的有效路线或任务要求。

- `walk_path`：至少三个经纬度点，每点顺序为 `[经度, 纬度]`，相邻点不能重合。
- `dist_limit_m`：正数，单位为米。
- `min_speed_mps` / `max_speed_mps`：一起设置，使用正数且下限不超过上限。相同的上下限表示恒速。
- 老配置仍可使用 `base_speed_mps` / `speed_amp`；其速度下限必须大于零。
- `auto_start_run`：是否执行预设的开始/结束按钮操作。
- `allow_coordinate_fallback`：默认 `false`。只有明确设为 `true` 时，识别失败才回退到固定坐标；该方式依赖界面尺寸与布局。

缺失或格式错误的配置、非法坐标、非有限数值和无效速度会报错退出，不会静默恢复成默认路线。
命令行配置错误返回非零退出码，并保留原文件。

## 按钮模板

当前预设流程为“开始乐跑 → 自由跑确认 → 暂停 → 结束 → 确认结束”。
这不等于学校的校园跑流程，代码没有完整处理随机打卡点、人脸核验或成绩确认。

在对应界面使用 `lepao capture` 截取当前版本的按钮，并按配置中的名称存入本目录的 `img/`：

| 配置字段 | 默认文件 | 对应按钮 |
| --- | --- | --- |
| `tpl_begin` | `img/begin_run.png` | 开始乐跑 |
| `tpl_free` | `img/free_run.png` | 自由跑确认 |
| `tpl_pause` | `img/pause_run.png` | 暂停（长按） |
| `tpl_end` | `img/end_run.png` | 结束 |
| `tpl_confirm_end` | `img/confirm_end.png` | 确认结束 |

仓库未附带 `free_run.png`；其他模板也需核对是否匹配当前测试 App。
自动操作默认要求模板完整且识别成功。缺少模板、识别失败或 ADB 操作失败会中止流程。
识别到按钮并执行点击仅能确认本地操作，没有验证服务端状态。

## 运行与结果

准备完成后，在仓库根目录运行 `lepao run`。
程序通过 MuMu 更新位置；模拟器连接、App 启动或位置更新失败会退出并报告错误。
本地达到目标距离后会尝试执行结束操作，并保留模拟器供人工检查。
异常中断时也应人工检查 App 状态，必要时手动结束测试。

显示的距离、速度和步数属于本地模拟值。步数仅用于诊断，不向 Android 写入伪造的传感器数据。
“本地模拟完成”不代表步道乐跑已经接收、认可或计入任务；程序没有实现官方成绩核验。

## 测试范围

在仓库根目录执行 `python -m pytest -q`。
回归测试使用假的 MuMu/UI 和本地数据，不启动真实模拟器，也不登录或上传记录。
